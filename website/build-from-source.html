从源码构建

适用于：无法或不愿直接拉取 GHCR 镜像、需要审计构建过程、或希望自定义镜像的场景。

前提

  • Git、Docker（镜像构建）；Dockerfile 内部使用 Node 构建前端，宿主机无需先生成 dist
  • 构建环境能访问镜像 registry、npm registry 与 Alpine 软件包源

构建 console 镜像

git clone https://github.com/nghqqa/MergePilot.git
cd MergePilot && git checkout v0.2.0-beta.6-rc.35.6-rc2   # 与官方镜像同源的源码 tag

# Dockerfile 在构建阶段执行 npm ci + vite build；本机历史 dist 不会进入镜像
# 版本号与提交号决定 /api/health 的 version/git_commit 字段
docker build -f docker/Dockerfile.canonical-console \
  --build-arg MERGEPILOT_VERSION=v0.2.0-beta.6-rc.35.6-rc2 \
  --build-arg GIT_COMMIT=ea72400af462b9f6dbf05318b1ef0ebb3bcc81d1 \
  -t mergepilot-console:v0.2.0-beta.6-rc.35.6-rc2 .
必须填写与实际源码相符的 MERGEPILOT_VERSION 与 GIT_COMMIT，否则 health 的身份信息不能用于核对。 若构建 main 或其他 commit 的发布后修正，请使用独立版本后缀和本地镜像标签， 不要标为官方 rc.35.6-rc2；范围见发布与源码范围。

可复现性

官方 digest 6d25fd1e…4cb 的构建源即 tag v0.2.0-beta.6-rc.35.6-rc2 （commit ea72400af462b9f6dbf05318b1ef0ebb3bcc81d1，构建注入的 GIT_COMMIT 与之一致）。源码同源不保证构建字节或行为验证结果完全相同； 构建时间、软件包源与构建参数都可能改变产物。自建后仍需核对 health、前端 bundle 并验证所用能力； 需要官方原制品时，直接按官方 digest 拉取。

接入 compose

编辑 deploy/selfhost/docker-compose.yml，把 console 的 image: 改为你的本地引用：

image: mergepilot-console:v0.2.0-beta.6-rc.35.6-rc2

其余配置不变。

离线 tar 途径

无法访问 GHCR 时，可使用离线 tar（SHA256 见 下载与校验）：docker load -i mergepilot-console-v0.2.0-beta.6-rc.35.6-rc2-offline.tar.gz， 先校验 tar 的 SHA256；加载后以同引擎的在线拉取记录比对，跨引擎不直接比较 image ID， 详见下载与校验。
