拓扑

服务镜像端口（宿主）说明
consoleGHCR 不可变 digest（见 下载与校验）127.0.0.1:48500→4730主控制台 + 多用户 API + cchain + RAG 编排
postgrespgvector/pgvector（manifest digest 钉死）不发布mu 库（pgvector 扩展），数据卷 pgdata

webhook-ingressnode:22-alpine + webhook-proxy.js127.0.0.1:48590→8080webhook-only 入口：仅放行 webhook 与 health
compose 全部服务 restart: unless-stopped；仅 console 与 webhook-ingress 发布端口且默认绑定回环； postgres/sidecar 仅内部网络可达。

卷与数据

  • pgdata — 数据库全部业务数据（唯一状态权威）
  • evidence — 审查证据包（只读回放）
  • model-cache — bge-m3 模型文件（可选）
  • keystore — cchain 运行绑定密钥（可选；权限 0600 语义由镜像内保证）

备份/恢复 = 备份/恢复 pgdata 卷或定期 pg_dump（见 升级与回滚）。

公网入口与反代拓扑（对外）

compose 默认仅在 127.0.0.1 暴露 48500（Console 全量）与 48590（webhook-ingress）。 对外暴露时须由部署者前置 HTTPS 反向代理或隧道（Nginx / Caddy / Cloudflare Tunnel）：

  • GitHub Webhook 路径（POST /api/mu/github/webhook）：推荐转发到 127.0.0.1:48590； webhook-proxy.js 仅放行该路径与 GET /api/health，其余路径一律 404。
  • Console 与 OAuth 路径（/login、/multiuser、/api/mu/auth/*）： 需要异地团队登录时经 HTTPS 反代转发至 127.0.0.1:48500 并加限流；若仅内网/Tailscale 访问，可不把 48500 暴露公网。
  • Gitee Webhook 路径（POST /api/mu/gitee/webhook）：48590 默认未放行该路径，须在反代中转发至 127.0.0.1:48500。

可直接复用的 Nginx / Caddy / Cloudflare Tunnel 完整配置模板见 安全加固清单， 公网连通性与 GitHub Delivery 验收步骤见 多租户与 webhook。

cchain 信任链（可选）

三项配置齐全后 cchain=READY，任一缺失即 BLOCKED（fail-closed，控制台如实显示）：

  • MERGEPILOT_MODEL_CACHE_DIR — 模型文件目录（挂载卷）
  • MERGEPILOT_PROVIDER_ATTEST_URL — 供应商证明静态端点（自建 nginx 即可）
  • MERGEPILOT_RUN_BINDING_KEYSTORE — 运行绑定密钥（经 rotate API 轮换）
