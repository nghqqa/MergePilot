快速开始

本页面向部署者。需要 Docker 与 Docker Compose v2、Git、Node.js ≥ 20（运行预检脚本）， 以及 GitHub App、OAuth App 和对应配置。耗时取决于凭据与网络入口准备情况。 已有实例的受邀成员请读首次使用。

以下命令固定到已发布预发布候选 rc.35.6-rc6（源码 c094ad1）；其发布之后合入 main 的修正不会自动进入该镜像，见 发布与源码范围。

先读·这是什么形态：MergePilot 是用户自托管产品—— Console、数据库、OAuth 配置与业务数据全部运行在部署者自己的环境中。 本机/内网部署适合本地评估与受限使用；GitHub OAuth 回调（本机评估除外）、自动 Webhook、 跨机器邀请认领需要部署者自己的公网 HTTPS Console 地址或其他可被 GitHub 与受邀用户访问的安全入口。GHCR 镜像为 Public 仅表示可匿名拉取镜像，不表示提供托管 Console 或公网入口。详见 多租户与 webhook。

1. 获取源码与模板

git clone https://github.com/nghqqa/MergePilot.git
cd MergePilot && git checkout v0.2.0-beta.6-rc.35.6-rc6
cd deploy/selfhost

2. 填写配置

cp .env.example .env && chmod 600 .env

必填项（生成命令见 配置参考）： POSTGRES_PASSWORD、CONSOLE_SESSION_SECRET、 GitHub App 四项、OAuth App 两项、LLM 四项。 App 的创建步骤见 多租户与 webhook。

3. 一键检查后启动

node preflight.mjs                    # 只读检查，关键项失败即退出
docker compose --env-file .env up -d
node preflight.mjs --live             # 启动后活体探测
curl http://127.0.0.1:48500/api/health

首次启动自动完成数据库 schema 初始化（至 v29），无需手工建表。

4. 初始化首任管理员，再邀请成员

  1. 空库先建管：部署者按仓库 首个平台管理员初始化（生产） 执行 SQL、身份硬校验与读回检查。生产保持 MU_ALLOW_FIXTURE_LOGIN=0； 邀请永不授予 platform_admin，不能靠邀请或首次 OAuth 登录自动创建管理员。
  2. 管理员登录：初始化后，使用与 SQL 绑定身份一致的 GitHub 账号登录你自己的 Console， 在「组织与接入」管理成员与邀请。
  3. 邀请业务成员：按平台数字 user id 创建邀请；受邀者用对应 OAuth 账号登录认领。 审批、应用修复与合并需 maintainer，platform_admin 无这些权限，见 角色矩阵。

本机登录入口为 http://127.0.0.1:48500/login；受邀成员的日常操作见 首次使用。健康检查成功只说明容器就绪，还需验证仓库绑定、webhook 与审查链路。

生产对外暴露：必须前置 TLS 反向代理并把回调地址改为 https 域名。 生产 Webhook 地址必须公网 HTTPS 可达（转发到本机 48590，入口实现不限—— 见 多租户与 webhook）。 明文 HTTP 不允许承载已认证会话（会话 Cookie 自带 Secure 属性）。详见 安全加固。
