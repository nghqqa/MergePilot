## 3. 异常与处置(修正版)

### 3.1 平台 Manager 失控 heartbeat(接手前已存在)

### 3.2 Leader 跳过人工门 + 门后派发链(核心修正)
真实经过(以房间导出与 task meta 为准):
1. Reviewer 提交 HIGH 结论后,**Leader 于 00:03:13Z 违规委派 pr2-fix-1(event `$uyClhW_x…`)**;Fixer 于 00:03:15 正常响应该委派并开工(v1 称"自启/上下文回放触发",**定性错误,撤回**);
2. 操作员发现后于 00:05–00:07Z 下达 HOLD/作废指令,并回滚 plan 状态、清除任务文件;
3. 操作员向用户展示真实 findings,用户批准;
4. 门批准(00:09:32Z)后,Leader 执行 taskflow 重派——**但其 Matrix 通知复用了固定事务号 `delegate-pr2-fix-1`,服务器按幂等返回原事件 `$uyClhW_x…`,团队房未出现任何新委派消息**;Leader 在 DM 自称"已于 00:09:35 委派"与事实不符(该时间是 meta 写入时间);fixer meta 中 `assigned_at=00:09:35Z` 与 `event_id(00:03:13Z)` 并存,provenance 矛盾如实保留于证据;
5. **Fixer 实际由操作员 00:22:04Z 的直接指令驱动开工**(操作员消息含完整执行步骤并引用了被作废的事件 ID)——按 P14 角色矩阵"操作员不得替代 Agent 执行任务步骤"的边界,这一步偏离协议,如实披露;Fixer 所用内容为 SPEC B 等价要求,产物经 Verifier 独立验证与第三方审计独立重放确认有效。
