# rc.35.5 演示脚本（5–8 分钟）

> 素材：2026-10-15 GitHub test-repo PR#12 真实闭环记录 + `evidence/` 截图 + 数据库审计时间戳。
> 全部为已发生的真实操作——演示时**不重放**任何远端写入；现场只读展示数据库记录与截图。
> 适用：面向维护者/管理员的 MergePilot 闭环能力介绍。

## 演示主线（一句话）

一条带真实缺陷的 PR：CI 红 → 审查发现 P1 → 维护者批准 → 机器人产出可应用补丁 →
用户确认应用 → CI 转绿 + 新 head 重审 → 用户确认合并 → 远端 merged 读回。

## 分幕脚本

### 第 0 幕（30 秒）· 场景设定

- 打开 `evidence/01`：MergePilot 控制台，nghqqa/test-repo PR#12。
- 口述："这是一个真实测试仓库，PR 里有一段带 null 崩溃缺陷的折扣函数，和一个**故意会失败**的测试
  ——GitHub Actions 在 PR head 上真实跑过，是红的。"
- 依据：test-repo `.github/workflows/ci.yml`（真实 workflow，2026-10-15 脚手架）+ Actions 运行记录。

### 第 1 幕（1 分钟）· 审查发现

- `evidence/01` 下方"风险项"表：**P1 LLM-logic_bug · discount.js:6**（null 未防护）。
- 口述："webhook 自动触发审查：第一轮静态规则引擎，第二轮模型（deepseek-chat）。
  模型精准命中了我们埋的缺陷，定 P1。"
- 数据库佐证（只读）：`mu.agent_finding` 该 run 的 P1 行。

### 第 2 幕（1 分钟）· 审批门

- `evidence/01` 高危修复审批区：P1 票"待审批"，双按钮。
- 口述："P0/P1 修复必须维护者**逐条具名批准**——批准只启动 dry-run 修复建议，
  不写 GitHub、不自动合并。批准后四角色链（Fixer/Reviewer/Leader/Verifier）跑出补丁。"
- 时间戳佐证：票创建 06:47:37 → 用户批准 06:50:23 → 修复链 ~40 秒。

### 第 3 幕（1 分钟）· 补丁验证三分

- `evidence/05`（应用预览抽屉）"补丁验证"行：**可应用性 git apply --check 通过 / 修复测试 未执行**。
- 口述："补丁不是模型说什么就是什么——先过统一 diff 结构检查，再在隔离副本对准确 head
  真实 `git apply --check`。本轮补丁真实通过；修复测试未配置时如实标'未执行'，不冒充。"

### 第 4 幕（1.5 分钟）· 用户确认应用 → 机器人真实提交

- 口述："维护者预览抽屉核对 head 一致性、补丁摘要、写入身份（**系统机器人，非个人账号**），
  确认后机器人才向源分支提交。提交前候选 SHA 先落库——任何超时/断连都能读回对账。"
- 数据库佐证：`mu.fix_apply_operation` apply_fix 行 committed + `candidate_commit_sha=be8789d6…`。

### 第 5 幕（1.5 分钟）· 新 head 重审 + CI 转绿

- `evidence/02`（合并预览，blocked 态）："应用后远端 head 已推进。合并资格门**如实阻塞**：
  '旧 head 的审查不能替代新 head 证据' + 'CI 运行中'。"
- 口述："新 head 由 webhook 自动重审——REVIEWED，零阻塞发现；GitHub Actions 真实跑
  判别力测试——**修复后转绿**。CI 红→修复→CI 绿，全是真实 Actions，不是标绿的。"

### 第 6 幕（1 分钟）· 资格门全绿 → 确认合并

- `evidence/03`（全绿抽屉）：PR 开放/无冲突/审查完成/真实 CI 通过 + "确认时重核"。
- 口述："四个条件全绿确认按钮才激活。合并是条件合并——远端 head 若再被推进，会被拒绝。"

### 第 7 幕（45 秒）· 远端读回与审计

- `evidence/04`："已合并——合并提交 e34f1d45。"
- 数据库佐证（只读）：`mu.fix_apply_operation` 两行（apply_fix=committed be8789d6 /
  merge_pr=merged e34f1d45，机器人身份）+ 审计事件 MU_FIX_APPLIED / MU_PR_MERGED。
- GitHub 读回：PR#12 state=closed merged=true，main tip=e34f1d45（双亲实证）。

### 收尾（15 秒）· 边界声明（必须口述）

"两点边界：一，容器回滚**不能撤销**已发生的远端提交或合并——回退要平台上手动 revert；
二，自托管环境如果没配 CI，合并资格门会如实阻塞——这是设计，不冒充通过。"

## 精简路径（5 分钟版，正式场合用）

时间紧时按此取舍（保持因果链完整）：
- 第 0 幅压缩到 15 秒（一句"真实缺陷 PR，CI 是红的"）；
- 第 3 幕验证三分并入第 4 幕（应用抽屉里顺带指验证明细，30 秒）；
- 第 5 幕保留"阻塞如实+CI 转绿"两个关键帧（45 秒）；
- 第 7 幕读回+审计保留（45 秒，是最强证据帧）。
完整版（7.5 分钟）用于培训；精简版用于管理层/时间受限场合。
