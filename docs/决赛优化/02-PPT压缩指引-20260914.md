# 决赛优化 · PPT 压缩指引（三页主讲 + 附录）· 2026-09-15 更新

> 评委原话：把 PPT 聚焦于审修质量和可靠性改进；多 Agent 方案压缩为 2～3 页；工具清单、完整 Skill 定义、通用架构细节放附录；明确合成案例、受控仓库与实际团队使用数据的边界。
> 本指引给的是页面结构与每页必须出现的"事实 + 证据 + 等级"，数字全部取自本轮真实输出（《00-事实核验表》）。
> **等级标签必须原样出现在页面角标，不得混写**：`REAL_EXECUTED`（真实运行/真实实验）· `LOCAL_REAL_SQL`（本地 PostgreSQL 真实 SQL，非 Agentic Database）· `CONTROL_PLANE_MECHANISM`（真实控制器+PG+测试，Agent 输出受控）· `SYNTHETIC`（合成数据/夹具/回放）· `NOT_EXECUTED` · `BLOCKED`。

## 主讲三页

### 第 1 页 · 角色职责与证据交接（同一个 PR）

| 版块 | 内容 | 等级 |
|---|---|---|
| 三角色互验 | Reviewer 出**风险依据**（finding F1：`payments.py:29`、L1、指向验收测试 `test_second_payment_request_for_same_order_is_idempotent`）→ Fixer 给**修复目标**（按 order_id 幂等）→ Verifier **只认测试**，不认 Fixer 自述 | CONTROL_PLANE_MECHANISM |
| 交接对象 | 每次交接都带：run_id · PR · 代码树 SHA（`git mktree`）· 测试命令与结果 · 证据路径；Controller/PG 是唯一权威状态，Element 消息只是交接证据 | CONTROL_PLANE_MECHANISM |
| 历史真实运行 | PR#1/2/3（AgentTeams/CoPaw，2026-08-29/30，SHA256 锁定回放）证明"人审门/409 终态"在真实 Agent 栈上成立 | REAL_EXECUTED（历史）|
| 角标 | "Element 上的本案例真实交接：NOT_EXECUTED（需启动 AgentTeams 栈并授权）" | NOT_EXECUTED |

### 第 2 页 · 失败返工与人工升级

| 版块 | 内容 | 等级 |
|---|---|---|
| 一次失败返工 | review#1 → fix#1（按 payment_id 去重，看似合理）→ verify#1 **FAIL**（真实 unittest 1/5 失败）→ 控制器写 `fix#2` + outbox「verify FAIL(第 1/3 次)，回退修复」→ fix#2 → verify#2 **PASS 5/5** → task PASS（真实 `stage_runs` 五行） | CONTROL_PLANE_MECHANISM |
| 上限与升级 | 连续 3 次 FAIL → `HOLD/verify_max_hold`，不派发第 4 次；缺验收测试 → `BLOCKED` → 退回 → 上限转人工；非 verifier 的 verify / 重复 event_id / 缺 VERDICT 快照 / 非 admin 提交 → 状态机不动 | CONTROL_PLANE_MECHANISM |
| 可靠性对照 | 长/跨文件 PR 的 CWE-22 由 SAST 送进人工门（risk_classify 仅 L1）；小上下文 → PARTIAL_CONTEXT 不得 PASS；注入注释零影响；伪造批准挡不住 MIGRATION L2；干净 PR 0 误报 | REAL_EXECUTED（确定性层）；模型轴 NOT_EXECUTED |
| 角标 | "真实 LLM 驱动的 Reviewer/Fixer：NOT_EXECUTED（付费调用需授权）" | NOT_EXECUTED |

### 第 3 页 · 数据库迁移安全与评估闭环

| 版块 | 内容 | 等级 |
|---|---|---|
| 代码测试过、迁移失败 | 基线 10,000 单 / 137 NULL / 2 重复支付 → rev1 代码测试 7/7 PASS、迁移 **SQLSTATE 23502** → 补取信息（legacy 覆盖 120 / 不可回填 17 / 规则 ≤20% → 修订候选）→ 同候选 rev2 **PASS 11/11** | LOCAL_REAL_SQL |
| 批准绑定版本，变化即失效 | 批准对象 = (验证记录, 代码头, 脚本摘要, 基线摘要)；`db_release_gate` 每次重算 11 项；追加提交 → STALE；目标数据摘要变化 → MISMATCH；迟到 PASS 回调不能复活 | LOCAL_REAL_SQL |
| **授权执行路径过闸** | 网关最终执行点 `l2_claim_ticket` 内强制闸门：STALE / 摘要变化 / 未批准 / 过期 → **不进 EXECUTING、无 execution_id、无上游写入**；并发 claim 只有一个成功；未绑定验证的票据行为不变；网关把拒绝映射为 `DB_RELEASE_GATE_REFUSED` | LOCAL_REAL_SQL |
| 交付方案包 | preflight / migrate / postcheck / rollback / manifest，绑定摘要；"试验库通过 ≠ 生产发布" | LOCAL_REAL_SQL |
| 评估闭环（RAG） | 观测（127 行 span 仅 12 个查询）→ 18 族 54 条标注、按族切分 → 基线 hit@1 75.0% → 调优集选策略 → held-out 一次回测 91.7%（退化 1 条如实列）→ 晋级 v2 并在后台显示版本 | REAL_EXECUTED（SYNTHETIC 语料，小样本）|
| 角标 | "PolarDB Agentic Database 分支：NOT_EXECUTED / PolarDB NOT CONNECTED；本页 SQL 结果来自独立 PostgreSQL 克隆库" | NOT_EXECUTED |

## 现场演示顺序（10 分钟）

1. `/rework`（3 min）：等级标签 → 场景 A 五行时间线 → 尝试 1 diff 与失败测试 → 退回原因 → 尝试 2 PASS → B/C/D 一屏。
2. `/pr4`（5 min）：验证链 ①→⑦ → 人工门：批准 → "回放：追加一次代码提交" → 再批准 **409 STALE_VERSION** → 重置 → 三候选 SIMULATED 分区 → 运行元数据（证据 SHA256 校验）。
3. RAG 页 + `/api/rag/status`（1 min）：策略 v2、证据、held-out 前后。
4. 边界收尾（1 min）：`/api/health.finals` 的 tiers；未完成项。
