## 一、开场用 30 秒说明

建议开场表述：

> MergePilot 的底层基座是 HiClaw/AgentTeams。我们不是要重新换一个 Agent 框架，而是希望在现有基座上补齐真实 Agent 协同 Trace，并按最新建议接入 AgentLoop，通过 LoongSuite 探针和标准 OTel GenAI Span 做结果与轨迹双评估。针对数据库方向，我们计划用一个跨仓 Schema 变更场景，串联 PolarDB RAG 的企业记忆和 AgenticDB Branch 的隔离验证。今天主要想确认这些能力的开通方式、可用范围和复赛验收口径。

## 二、必须询问的问题

### A. AgentLoop 与 LoongSuite（14 问）

- **A1【P0】** 参赛团队能否申请 AgentLoop 试用或专项资源？申请入口、审批周期和费用如何？
- **A2【P0】** 对自研 Python HiClaw/AgentTeams 控制面，官方推荐 LoongSuite Pilot、Python 语言探针、`loongsuite-otel-util-genai` 手动埋点，还是组合接入？LoongSuite Pilot 当前是否原生支持 HiClaw/AgentTeams？若不支持，官方是否认可"标准 OTel SDK + 手动 GenAI Span"作为等效接入路径？
- A3【P1】自动 Python 探针和 `loongsuite-otel-util-genai` 是否可以共用同一 Trace Provider/Exporter？推荐的版本组合是什么？
- A4【P1】AgentTeams 的 Manager、Reviewer、Fixer、Verifier 是否应分别建 Agent Span？官方推荐的 Span 树是否为 `Entry → Agent → ReAct Step → LLM/Tool/Retrieval/Memory`？
- A5【P1】Matrix 消息、Controller 状态、Gateway 决策和人工审批应使用 Span、Event、Link 还是 Attribute 表达？
- A6【P1】跨进程、跨容器和 Matrix 异步消息如何传播 `traceparent`？AgentLoop 是否支持 Span Link 展示异步交接？
- A7【P1】Trace 中允许记录哪些内容：工具参数摘要、Finding、Schema 变更、模型消息和验证结果？Prompt/Response 是否默认采集？
- A8【P1】LoongSuite 的端侧脱敏能否覆盖代码、PAT、数据库连接串和自定义 Attribute？是否支持 allowlist 字段策略？
- A9【P1】AgentLoop 自定义评估器是否支持同时读取 `input`、`output`、`agent_trajectory`、`tool_context` 和 `rag_context`？（若不支持，是否有等价的属性约定或旁路上传机制）
- A10【P1】轨迹评估器能否调用自定义 Skill/MCP 完成权限、规则和知识库校验？
- A11【P2】评委建议的"结果评估与轨迹评估"是否有推荐指标、预置模板或示例数据集？
- A12【P2】探针的性能开销、采样率、Trace 保存周期和费用如何计算？复赛演示推荐什么采样策略？
- A13【P2】复赛答辩是否可以展示 AgentLoop 控制台截图、真实 Trace ID 和评估任务详情？
- **A14【P0】** 官方是否提供 HiClaw/AgentTeams 或自研控制面接入 AgentLoop 的最小可运行样例？样例中异步交接（消息队列/派单）如何表达 Span Link？

### B. PolarDB RAG（8 问）

- **B1【P0】** 复赛团队可申请哪一种 PolarDB RAG：PolarDB PostgreSQL、PolarSearch，还是独立 RAG 引擎？
- B2【P1】是否提供测试实例、OSS、Embedding 模型和 Chat LLM 额度？（特别请确认 Embedding 模型维度——当前本地知识库为 384 维向量，如云上模型维度不同需要重建索引）
- B3【P1】知识库是否支持多仓库代码、Schema、研发规范、人工驳回和发布结果等混合数据？
- B4【P1】是否支持通过 API/SDK/Skill 进行检索，而不只是控制台问答？
- B5【P1】RAG 结果能否返回文档 ID、Chunk、相似度、知识库版本和 citation？
- B6【P1】是否建议对"成功经验"和"失败/驳回经验"使用不同知识库或 metadata 状态过滤？
- B7【P1】代码和数据库 Schema 上传到 RAG 时，赛事方对数据脱敏、保留时间和跨地域有何要求？
- B8【P2】是否可以让 MergePilot 保留本地静态 Skill，并把 RAG 只作为 advisory context？

### C. AgenticDB Branch（9 问）

- **C1【P0】** AgenticDB Branch 当前支持 PolarDB MySQL 还是也支持 PolarDB PostgreSQL？（公开资料显示 PG 版 Agentic Database 处于公测，请确认参赛可用性与地域）
- **C2【P0】** 参赛团队是否可以申请 Branch 公测资格？需要实例规格、地域和白名单吗？公测期间无 SLA 对演示的影响如何处理？
- **C3【P0】** Branch 能否通过 SQL、OpenAPI 或 SDK 自动创建、切换、查询和销毁？失败分支的报错信息能否被程序读取用于数据断言？
- C4【P1】单个实例允许同时创建多少 Branch？创建和销毁的 SLA、资源上限和并发限制是什么？
- C5【P1】是否支持带真实脱敏数据的库级 Branch？数据是否在创建时刻保持一致快照？
- C6【P1】评委建议的"失败候选留在 Branch 中"是要求保留现场，还是只需保留失败证据后自动清理？
- C7【P1】Branch 是否支持 Schema Migration、回填、唯一约束、索引和事务一致性验证？
- C8【P1】Branch 是否支持跨库或跨服务 Schema 变更的验证？
- C9【P1】如果 Branch 不支持当前引擎或结构，官方认可的替代方案是什么？

### D. 赛事验收与材料（7 问）

- **D1【P0】** 复赛是否允许在首次提交后追加真实 Trace、RAG 检索结果、Branch 执行日志等云上验证材料或更新 Demo？请一并确认最终提交截止时间与答辩形式（现场 / 录屏 / 远程共享屏幕）。
- **D2【P0】** 评审对数据库与可观测方向的要求是必须完成真实云上部署验证，还是接受"本地闭环 + 清晰的云上设计"？两者在评分上如何取舍？
- D3【P1】是否需要提交完整 Trace、评估任务、SQL、数据集和 Branch 日志，还是截图和摘要即可？
- D4【P1】复赛 Demo 是否允许使用外部云账号、临时实例和受控脱敏数据？
- D5【P2】对"生产可用""真实 E2E""已验证"的措辞，评委希望采用怎样的边界说明？
- **D6【P0】** 如果部分服务（如 AgentLoop 账号、Branch 公测资格）因地域、账号或审批限制在赛前无法开通，是否接受材料将其标注为 DESIGN_ONLY / BLOCKED_UPSTREAM 并列为决赛路线图？
- D7【P2】评委是否建议把旧的受控 benchmark 结果和新的 AgentLoop 轨迹评估放在同一页，还是分开呈现？

## 四、会上不要主动承诺

以下说法在没有新证据前不要使用：

- "我们已经接入 AgentLoop"；
- "我们的 RAG 已经是企业长期记忆"；
- "我们已经支持 AgenticDB Branch"；
- "系统可以自动完成生产数据库迁移"；
- "当前 benchmark 就是 AgentTeams 真实效果"；
- "多 Agent 必然优于单 Agent"；
- "项目已经 production ready"。

建议替代表述：

- "底层已经是 HiClaw/AgentTeams，当前补的是目标场景的真实 Trace 验证"；
- "本地 RAG 已有雏形，云上 PolarDB RAG 接入待资源确认"；
- "AgenticDB Branch 处于能力预研和公测资格确认阶段"；
- "我们将把未验证能力明确标为 NOT_VERIFIED"。
