# MergePilot 复赛更新版项目方案 - 逐页内容

冻结版本：`v0.1.0-preview.3`，tag / merged main `379744d0f6755bf04ed4d5eab2fc00bd504849be`。

## P1 封面

**标题：** MergePilot

**副标题：** 把多 Agent 代码协作放进确定性、可回滚、可审计的交付控制面

**短文案：** AgentTeams Runtime · Policy Gateway · 6 Skill DAG · Read-only Operations Console

**口播：** MergePilot解决的不是“让模型再多写一点代码”，而是让多Agent代码协作具备工程控制面。Agent负责语义判断，确定性Controller负责状态、交接、审批、回滚和审计。今天展示的是Windows 11 + WSL2本地Preview，不是生产系统。

**证据：** `README.md`；Release `v0.1.0-preview.3`；commit `379744d`。

**边界：** `production_verified=false`，不得称production ready。

## P2 初赛承诺经过工程验证后收敛

**标题：** 初赛设计没有被推翻，而是从角色设想收敛为可验证系统

**页面要点：**

- 六个逻辑角色 -> 四个运行时Agent承载六类职责。
- 手工handoff -> Workflow Controller确定性交接。
- 初赛旧称（不沿用）“MCP sidecar” -> GitHub MCP隔离服务。
- 初赛旧称（不沿用）“可观测侧车” -> 审计与可观测平面。
- 手工拼接Demo -> Preview安装包、只读控制台和冻结证据。

**口播：** 初赛按职责画了六个逻辑Agent。落地后发现Triage和Fix Planner更适合成为有Schema、deadline和失败闭合能力的Skill阶段，因此运行时收敛为四个Agent。我们减少了两次模型交接，但保留了全部职责，这是工程收敛，不是功能缩水。

**证据：** `docs/初赛证据索引.md`；`docs/复赛材料/00-材料约束.md`；`tools/workflow-controller/`。

**边界：** 初赛材料是历史快照，不回写当前能力。

## P3 问题与价值

**标题：** 多Agent真正难的不是生成，而是控制交接、权限和失败

**页面要点：**

- 交接失控：乱序、重复、超时、进程崩溃。
- 权限失控：Worker接触PAT，高风险写入缺少审批。
- 证据失真：成功截图无法证明路径、状态和清理结果。
- MergePilot把语义决策与确定性治理拆开，任何不确定状态fail-closed。

**口播：** 单个Agent能够给出建议，但无法独自承担状态一致性、授权、幂等和崩溃恢复。MergePilot把这些职责放到Controller、Gateway和审计事实中，让Agent只承担适合模型的语义判断。

**证据：** `docs/M3-B4-审批票据与Action-Outbox设计.md`；`evidence/m3b-b4e/`；`evidence/m3b-b5/`。

**边界：** 不宣称所有外部Agent运行时故障均已解决。

## P4 当前总体架构

**标题：** 一条PR链路，被拆成语义协作、确定性控制和受治理执行

**页面链路：**

`GitHub PR -> Workflow Controller -> AgentTeams / HiClaw -> 6 Skill DAG -> Policy Gateway -> GitHub MCP`

**底部平面：** PostgreSQL状态与审计、pgvector案例检索、MinIO对象与配置证据、本地Trace / OTel。

**口播：** Controller是唯一流程状态权威，AgentTeams只负责语义协作。Skill以结构化合同执行，Gateway决定是否允许工具调用，GitHub MCP只执行经过治理的操作。底部数据和证据平面让每次状态变化都能回溯。

**证据：** `docs/assets/mergepilot-architecture.svg`仅作历史参考；当前口径以本页和`docs/复赛材料/00-材料约束.md`为准；`tools/workflow-controller/`；`tools/policy-gateway/`。

**边界：** GitHub MCP是隔离服务，不称sidecar。

## P5 四个运行时Agent承载六类职责

**标题：** 只有需要独立身份和决策边界的职责才保留为Agent

**页面要点：**

- Manager / Coordinator：接入、拆解、路由和收口。
- Reviewer：安全、质量和规范审查。
- Fixer：生成修复并通过治理链提交。
- Verifier：复测、证据核对和回滚判定。
- Triage由`diff-parse + risk-classify`承担。
- Fix Planning收敛为Fixer规划阶段与Controller状态。

**口播：** Agent数量不是能力指标。Triage和Fix Planning没有独立凭证和扩缩容需求，拆成Agent只会增加上下文损耗。当前四个运行时身份与六类职责更符合最小权限和可恢复性。

**证据：** `config/souls/`；`tools/agentteams/`；`docs/附录A-Agent-Identity清单.md`。

**边界：** 不再写“六个已部署Agent”。

## P6 六类Skill组成可验证DAG

**标题：** Skill把模型输出约束为可测试、可超时、可复算的工程动作

**页面要点：**

1. `diff-parse`
2. `risk-classify`
3. `sast-scan`
4. `test-runner`
5. `pr-lifecycle`
6. `case-retrieval`

统一合同：Schema、deadline、原子输出、fail-closed、证据摘要。

**口播：** 六类Skill不是六段Prompt，而是具有输入输出Schema、超时和错误码的工程组件。Reviewer、Fixer和Verifier可以组合调用，但流程状态仍由Controller推进。

**证据：** `skills/`；`evidence/m4/m4f/verification.txt`；`docs/M5-0-HiClaw-Live设计冻结.md`。

**边界：** RAG当前为advisory，不宣称已提升Reviewer/Fixer准确率。

## P7 Controller让交接成为状态机

**标题：** Agent失联或重复消息不会把流程变成猜测

**页面要点：**

- PostgreSQL保存任务、阶段、attempt和revision绑定。
- Outbox负责派发，幂等键阻止重复推进。
- timeout进入HOLD；late event按CAS条件恢复。
- crash recovery从磁盘事实恢复，不依赖内存猜测。

**口播：** Controller把review、fix、verify以及回滚阶段写进状态机。消息可以重复，进程可以重启，但只有满足当前状态和revision条件的事件才能推进。

**证据：** `tools/workflow-controller/controller.py`；`tools/workflow-controller/m4f_ingress.py`；`evidence/m3b-b4e/`；`evidence/m3c/`。

**边界：** `revision_producer_contract=NOT_VERIFIED`。

## P8 PAT被锁在GitHub MCP隔离服务

**标题：** Agent可以提出动作，但不能绕过Gateway直接写GitHub

**页面要点：**

- Worker只持角色token，不持GitHub PAT。
- Policy Gateway校验角色、仓库、工具、方法、路径和revision。
- 高风险写入要求L2审批与单次授权。
- GitHub MCP执行通过治理的调用，PAT仅进入该隔离服务。

**口播：** Reviewer、Fixer和Verifier即使被错误提示诱导，也拿不到PAT。所有写操作先经过Gateway；保护路径、错误revision或缺少审批都会稳定DENY或HOLD。

**证据：** `config/m5-0c/real-github-policy.yaml`；`tools/policy-gateway/gateway.py`；`evidence/m3b-b5/`。

**边界：** 不称MCP sidecar；不展示任何真实token。

## P9 数据、审计与可观测各司其职

**标题：** 状态、知识、对象和Trace分层保存，不用一个“侧车”概括全部

**页面要点：**

- PostgreSQL：任务、阶段、Outbox、审批、结构化审计。
- pgvector：案例检索与相似度结果。
- MinIO：方向感知配置和对象证据。
- 本地Trace / OTel：跨Controller、Gateway、Skill的关联链。
- SLS：后续云端出口，不写成已完成。

**口播：** 我们把“可观测侧车”改成审计与可观测平面，因为当前不是每个Agent旁边部署一个sidecar。结构化审计、本地Trace和未来SLS是不同完成状态，材料中分别陈述。

**证据：** `tools/audit-db/`；`tools/trace_aggregator.py`；`docs/M6A-OTel-Observability设计冻结.md`；`docs/M6B-SLS-Observability设计冻结.md`。

**边界：** `database_verified=false`，`audit_producer_contract=NOT_VERIFIED`；云SLS未完成。

## P10 失败时先停住，再依据事实回滚

**标题：** 自动化的底线不是“总能成功”，而是失败后不留下未知状态

**页面流程：** `verify FAIL -> HOLD -> revision / approval checks -> revert child-run -> re-verify -> RECOVERED or HOLD`

**页面要点：** WAL / journal先于mutation；receipt独占发布；锁与资源按owner逆序清理；primary错误不被rollback错误覆盖。

**口播：** 回滚不是随便再提交一次。系统先核对revision、审批和当前状态，任何读取失败或漂移都进入HOLD。回滚完成后还要重新验证，失败则升级人工，不进行第二次盲目回滚。

**证据：** `evidence/m3c/`；`tools/harness/mp_gh4_harness.py`；run35 receipt与journal证据。

**边界：** 不把历史脚本触发证据表述为所有场景均已生产自动回滚。

## P11 run35证明整条E2E路径可以闭合

**标题：** 17阶段、16项前置和6条路由边在同一真实运行中收敛

**页面数字：** 17 stages complete；16 / 16 prerequisites；6 / 6 route edges；receipt verified；Matrix verified。

**口播：** run35不是合成成功页。它从前置检查、网络、容器、防火墙、中继、数据库、路由探针、Gateway、Agent、Receipt和Matrix一路推进到complete。控制台仍明确显示direct routing为false，因为路径经过wsl-user-relay。

**证据：** workspace evidence bundle `temp/m8gh4-run27/evidence/run35_output.json`；`session_run35_live_final.json`；`docs/preview/projections/complete.run35.json`。

**边界：** 本地真实E2E不等于生产验证；`direct_routing_verified=false`。

## P12 只读控制台让证据在30秒内可判断

**标题：** Complete、Failed和Stale都由同一白名单投影诚实呈现

**页面要点：**

- 17阶段时间线与首个稳定错误。
- 六边路由矩阵，Segment A / B与应用层结果。
- Receipt、Matrix、cleanup和五项真实性边界。
- GET-only、loopback-only，无apply、delete、rewire或rollback控件。

**口播：** 成功时展示完整证据；失败时第一个稳定错误和失败边立即置顶；上游失联时保留最后良好数据并标成stale。控制台观察系统，不操作系统。

**证据：** `.impeccable/review/desktop.png`；`.impeccable/review/desktop-failed.png`；`tools/demo_console/live_assets/e2e-status.html`。

**边界：** 它不是生产管理后台，也没有RBAC或写操作。

## P14 数据显示改善，也显示代价和不足

**标题：** 小样本评测中误报下降，但成本上升且决策准确率未改善

**页面数据：**

- Precision：36.36% -> 57.14%。
- F1：48.00% -> 63.16%。
- Recall：70.59% -> 70.59%。
- FP：21 -> 9。
- Token：+32.95%；API请求：+80%。
- Decision accuracy：50% -> 40%。

**口播：** 这组N=10乘2的受控本地评测显示，多角色编排主要减少误报，但没有提升召回，决策准确率反而下降，同时增加token和请求成本。因此它是方向性证据，不是“多Agent必然更好”的结论。

**证据：** `benchmark/formal-summary.md`；`benchmark/raw-runs/`；`benchmark/freeze_formal_results.py`。

**边界：** 单模型、合成fixture、每组仅10例、非真实Gateway/GitHub/HiClaw全链。

## P15 当前交付完整，但下一步仍是验证而不是夸大

**标题：** 复赛交付聚焦三件事：可运行、可证明、可继续验证

**页面要点：**

- 已交付：更新方案、Preview代码包、现场与录屏Demo、声明证据矩阵。
- 下一步：独立Windows 11物理机验收；多仓库与更大样本评测；SLS云出口；外部用户反馈。
- 保持五项真实性边界和`direct_routing_verified=false`。

**口播：** 当前版本证明了本地Preview能够安装、运行、诊断、回滚和展示证据。下一阶段不是再堆Agent，而是补独立机器验收、扩大真实样本，并把待验证边界逐项转成可复算证据。

**证据：** `docs/复赛材料/04-声明证据矩阵/声明证据矩阵.md`；Release `v0.1.0-preview.3`。

**边界：** External、application integration、database、production、revision producer和audit producer均未验证。
