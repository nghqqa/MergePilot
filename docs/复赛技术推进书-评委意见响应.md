> 适用范围：复赛后续研发、技术答疑、决赛候选路线

## 1. 项目定位

MergePilot 是面向高风险 Pull Request 的人机协同审修与门控交付系统。

系统自动完成：

- PR 语义审查与风险分类；
- 修复方案生成与受控执行；
- 测试、静态扫描和验证；
- 审计证据、Trace 和历史经验沉淀。

系统不对所有变更无条件自动合并或回滚：

- 低风险且验证通过的变更，可按策略自动推进；
- L2 数据库、破坏性操作、权限冲突和多次验证失败，必须进入 `HOLD`；
- 正式合并、生产数据库变更和回滚，受 Policy Gateway 与人工审批约束。

一句话定位：

> **MergePilot 是基于 HiClaw/AgentTeams 的自动审修、门控交付系统：Agent 负责语义判断，Controller 负责状态与恢复，Gateway 负责权限，人工负责高风险最终授权。**

## 2. 当前基线与边界

### 2.1 已有基础

- 底层运行基座为 HiClaw/AgentTeams；
- 4 个运行时 Agent：Manager/Coordinator、Reviewer、Fixer、Verifier；
- 6 类 Skill 已形成公共 Contract 和测试体系；
- Workflow Controller、Policy Gateway、审批票据、失败恢复和回滚链路已有大量本地/隔离环境证据；
- 本地 PostgreSQL 16 + pgvector 的审计与案例检索能力已有验证；
- 正式受控 benchmark：20 个合成 fixture × A/B × 3 次，共 120 runs；
- AgentLoop、云上 PolarDB RAG、AgenticDB Branch 尚未接入当前生产运行链路。

### 2.2 必须保持的真实性边界

| 能力 | 当前状态 | 说明 |
|---|---|---|
| HiClaw/AgentTeams 底座 | 部分 VERIFIED | 已有隔离 AgentTeams 协议和运行证据，仍需补当前目标场景的真实链路证据 |
| Controller 状态机 | 部分 VERIFIED | 本地/隔离环境已测，云上生产链路未验证 |

## 3. 复赛唯一主线场景

选择一个跨仓库 Schema 变更作为三条评委意见的共同载体：

```text
订单服务仓库 + 报表服务仓库 + PolarDB Schema/Migration + 历史脏数据
```

目标演示链路：

```text
PR 提交
→ Manager 分析跨仓影响
→ PolarDB RAG 检索关联仓库、Schema、规范和历史案例
→ Reviewer 生成风险与候选方案
→ 在多个 AgenticDB Branch 上并行验证
→ Verifier 执行数据断言、兼容性和恢复检查
→ 失败方案保留失败证据，不进入成功经验
→ 通过方案进入人工审批
→ 正式执行
→ 真实结果回写 RAG
→ AgentLoop 同时评估结果与执行轨迹
```

如果云资源或公测资格未获得，演示必须降级为设计/本地验证，并显式标注未验证项，不使用模拟结果冒充云上能力。

## 4. 工作包与验收门槛

### WP0：资源与权限确认（最高优先级）

确认 AgentLoop、PolarDB RAG 和 AgenticDB Branch 的账号、地域、权限、额度、API/SQL 接入方式及数据合规要求。

退出条件：形成《云能力确认表》，每项有 `可用 / 待申请 / 不可用` 结论和替代方案。

### WP1：真实 HiClaw/AgentTeams 协同证据

目标不是重新接入 AgentTeams，而是证明现有 MergePilot 确实在该基座上完成非固定顺序协同。

必须验证：

- Reviewer → Fixer → Verifier 的结构化 handoff；
- Reviewer 与 Verifier 分歧时的仲裁；
- Verifier 失败后的有限重派；
- 工具失败后的异常重派；
- 人工拒绝后的恢复路径；
- L2、超时、循环超限统一进入 `HOLD`；
- 每个阶段有 run/stage/attempt/idempotency provenance。

证据：真实 AgentTeams run、完整 Matrix/Controller 事件、工具调用记录和最终审计摘要。

### WP2：AgentLoop + LoongSuite 标准 OTel GenAI Trace

评委最新建议已明确技术路径：接入 AgentLoop，并使用 LoongSuite 探针或兼容方式采集、分析和展现标准 OTel GenAI Trace。

LoongSuite 不是单一接入模式，当前预研结论为：

- LoongSuite Pilot 适合其接入中心已明确支持的本机 AI Coding Agent；
- 语言/框架探针可以自动采集受支持的 LLM SDK 与框架调用；
- MergePilot 自研的 Controller、Matrix handoff、Gateway、审批和 Skill 语义，预计需要通过 `loongsuite-otel-util-genai` 与 OpenTelemetry SDK 补充自定义 GenAI Span；
- 自动探针和手动 GenAI Span 必须使用单一 Trace Provider/Exporter 方案，避免同一进程初始化两套链路；
- 最终接入模式需在评委答疑和 AgentLoop 接入中心确认，不预设 HiClaw 已被 LoongSuite Pilot 原生支持。

目标 Span 层级：

```text
Entry（一个 PR 审修任务）
└─ Agent（Manager/Reviewer/Fixer/Verifier）
   └─ ReAct Step / Workflow Stage
      ├─ LLM
      ├─ Tool（Skill / Gateway / GitHub MCP）
      ├─ Retrieval / Rerank（PolarDB RAG）
      └─ Memory（案例回写）
```

跨进程/跨组件需传播 `traceparent`，并将 `run_id`、`task_id`、`stage`、`attempt`、`agent_role`、`tool_name`、`policy_decision` 等作为受控 Attribute 或 Baggage 传播。Prompt、响应、代码、数据库内容和凭证默认不直接上报；如确需采集，只允许脱敏摘要、哈希或外部证据引用。

传播与载体细则：

- HTTP 边界继续沿用现有 W3C `traceparent` 注入/提取实现（Gateway → MCP 已具备）；
- Matrix 异步消息：任务载荷新增 `traceparent`（及 `mp.run_id`）字段作为自定义 carrier，派单模板同步扩展；消费方在其新 span 上以 **Span Link** 关联生产方 span，表达异步交接；
- 敏感红线同样适用于消息载体：Matrix 消息中不得出现 Prompt 正文、代码全文、PAT、数据库连接串；跨任务传递一律以产物路径 + 证据引用替代内容拷贝；
- 本条属确定性工程，不依赖答疑结果，列入会后 24 小时优先实施项。

结果评估：

- Finding 的 TP/FP/FN；
- Precision、Recall、F1；
- 决策准确率；
- 测试和验证是否通过；
- 权限和策略是否违规。

轨迹评估：

- 工具选择是否合理；
- 是否调用未授权工具；
- 是否存在无效重复步骤；
- Reviewer → Fixer 上下文是否完整；
- 是否正确触发重派和人工升级；
- token、时延、循环次数和阶段失败归因。

轨迹评估方法：

- 数据来源：真实 AgentTeams run 的标准 OTel GenAI Trace（接入 AgentLoop 后取平台侧；接入前用本地 OTLP 导出兜底，两侧基于同一 span 命名合同）；
- 输入集复用：复用 benchmark 现有 20 个合成 fixture 及其预注册配置作为评估输入，不新增基线噪声；同一批 fixture 同时产出"结果分 + 轨迹分"两张独立分数板；
- 期望轨迹标注：每个 fixture 由人工预先标注期望轨迹要素（应使用的 Skill/Gateway 工具序列、预期重派触发点、禁止出现的调用、handoff 应携带的字段），标注在评测开始前冻结并存档；
- 规则评估器：确定性断言——调用未授权工具、缺失期望关键步骤、无效重复步骤超阈值、重派次数越限、handoff 字段缺失、policy 决策漏记；命中即扣分，全程机器可复算；
- LLM-as-Judge 评估器：仅用于无法穷举规则的开放维度（工具选择合理性、Reviewer→Fixer 上下文完整性、目标偏离程度）；固定 rubric、固定 judge 模型与参数，输出连同理由留档，并抽样做人工一致性校准；
- 展示纪律：结果评估与轨迹评估始终分开呈现，不合成单一总分；
- 红线：本地受控 adapter 的 120-run benchmark 只证明结果层 A/B 对比，**不得表述为"真实 AgentTeams 轨迹评估"**；轨迹分只有在真实链路 Trace 上计算出后才可标 VERIFIED。

接入验收：

- AgentLoop 中能查看完整的 `Entry → Agent → Step → LLM/Tool/Retrieval` 调用树；
- AgentTeams/HiClaw、Controller、Gateway 与 Skill Span 使用同一个 Trace ID；
- Token、时延、错误状态、工具调用和模型身份能够正确展示；
- 端侧脱敏开启，真实 PAT、数据库凭证和用户代码不落入可观测后端；
- 探针开销经过对照测试，记录时延、CPU 和内存增量；
- 至少一个真实 Trace 同时运行结果评估器和轨迹评估器；
- 跨进程、跨容器与 Matrix 异步交接后，仍能在 AgentLoop 中还原为单一 Trace ID 的完整调用树（对应集成测试进 CI 门禁）。

### WP3：PolarDB RAG 企业长期记忆

知识库分为：

- Finding 与修复案例；
- 关联仓库、API、Schema 和依赖关系；
- 安全、Migration、测试和发布规范；
- 人工驳回、Branch 失败、线上回滚和真实发布结果。

每条案例必须带生命周期状态：

```text
candidate → validated → deployed
                 ├→ rejected
                 └→ rolled_back
```

规则：

- 只有真实验证和交付结果明确的案例才能作为成功经验；
- rejected/rolled_back 案例只能作为风险提示；
- Reviewer 使用 RAG 结果时保留 citation、知识库版本和检索时间；
- RAG 是 advisory，不能覆盖静态扫描、Verifier 或 Policy Gateway。

"有 RAG / 无 RAG"A-B 对照实验（列入 D5–D6 验收）：

- 控制变量：同一 PR 集合（从现有 fixture 子集选取）、同一模型版本与采样参数、同一执行环境；
- A 组：无 RAG 注入；B 组：注入 RAG advisory，每条检索结果必须携带 citation、知识库版本（kb_version）与生命周期状态（validated/deployed/rejected/rolled_back）；
- 比较指标：误报率、漏报率、关联仓库识别命中、Schema 关联对象识别命中、"应补必要测试"识别、token 成本增量；
- 结论纪律：样本量有限，报告口径为"对照观察"，不写成因果证明，不外推出"长期记忆普遍有效"的一般结论；数字与其局限一并公示。

### WP4：AgenticDB Branch 数据验证

准备一份带有重复值、空值、历史残留或回填中断痕迹的脱敏基线。

并行验证至少两个方案：

- 方案 A：直接添加唯一约束；
- 方案 B：先清洗/回填，再添加约束。

Verifier 检查：

- Schema 迁移是否成功；
- 数据断言是否满足；
- 新旧应用是否兼容；
- 中断后能否继续；
- 失败 Branch 是否不影响源对象；
- 通过结果是否可以进入人工审批。

官方文档显示 Branch 当前为公测能力，且存在引擎、表结构和约束限制。必须先确认 MergePilot 目标 PolarDB 引擎是否支持该能力。

AgenticDB Branch 降级树（云资源或公测资格不可得时按序降级，逐级声明，不得跨级）：

1. **PolarDB AgenticDB Branch**（首选）：公测资格与目标引擎可用性经确认后使用；
2. **PolarDB-PG 影子 Schema / 克隆库 / 独立隔离测试库**：同引擎隔离机制的工程等价演示，标"分支能力等价实现，非 AgenticDB Branch 产品能力"；
3. **本地兼容环境**（现有 PostgreSQL 16 + pgvector 容器栈）：仅用于机制演示（多隔离 schema + 断言脚本），标 NOT_VERIFIED_FOR_CLOUD，材料中不得出现任何云产品能力暗示；
4. **均不可行**：该工作包整体转 DESIGN_ONLY 或 BLOCKED_UPSTREAM，进入决赛路线图。

通用纪律：任何一级 fallback 都不等价于真实 AgenticDB Branch，材料、Demo 口播与架构图必须保持区分，不得混写。同时，Branch 创建/执行/销毁操作必须注册进 Policy Gateway 工具矩阵（建议 L2 级，凭票据授权生产执行），不允许存在旁路工具调用。

- 工具权限矩阵；
- 统一 OTel Trace；
- 失败重派与人工拒绝恢复；

## 5. 任务完成契约（DoD）

把散落在 Verifier SOUL 与 Controller 常量中的判定规则收敛为一份对外可见的任务完成契约。所有评测、材料和口播只能依据下列字段下结论：

统一记录字段：

| 字段 | 含义 |
|---|---|
| `VERDICT` | 最终结论：PASS / HOLD / FAIL(中间态) / BLOCKED |
| `tests` | 本次执行的测试集与结果（Skill sast_scan、测试运行、Verifier 数据断言输出） |
| `policy` | Policy Gateway 决策汇总（ALLOW/DENY/HOLD）及生效 policy_hash |
| `audit_receipt` | 审计库事件 ID 与审批票据 ID（不可变事实源） |
| `l2_risk_state` | NONE / TICKET_REQUIRED / TICKET_APPROVED / REJECTED |
| `provenance` | run_id / task_id / stage / attempt / 幂等键，贯穿 Controller 状态机 |

四种状态的定义：

**PASS（任务完成）**
- 完成条件：Verifier 双判据满足（原有 findings 全部解决且无新增问题）；tests 全绿；policy 无未决 DENY；`l2_risk_state ∈ {NONE, TICKET_APPROVED}`；
- 终止条件：无——低风险变更按策略自动推进交付；L2 变更先转 HOLD(m5_verify_passed) 待票据后交付；
- 必要证据：VERDICT 记录、tests 结果、policy 汇总+hash、audit receipt、Trace 链接。

**HOLD（交人工，非失败态）**
- 触发条件：L2 危险动作待票据；verify 失败达 MAX_VERIFY_ATTEMPTS=3；回滚后复验失败（不允许第二次回滚）；producer 超时 reconcile；
- 终止条件：人工 approve → 从断点原子恢复；人工 reject → 任务进入 rejected 终态，驳回原因沉淀进知识库风险案例；等待超窗保持 HOLD 并告警；
- 必要证据：HOLD 原因码（如 hold_reason=verify_max）、审批票据记录、approve/reject 决策人与时间戳。

**FAIL（中间态，只允许转换为 HOLD 或消除）**
- 触发条件：单轮 verify 未通过或修复引入回归；
- 终止条件：达到重派上限仍未通过 → 转 HOLD(verify_max)；否则 FAIL 不是合法落点；
- 必要证据：fail_reason、修复 diff、attempt 序号与 provenance 链。

**BLOCKED（外部依赖缺失，非系统缺陷）**
- 触发条件：云资源、公测资格、上游平台服务不可用或超期未批；
- 终止条件：资源到位自动恢复；或在复赛语境下降级为 DESIGN_ONLY / BLOCKED_UPSTREAM 并如实标注；
- 必要证据：阻塞原因、依赖对象、解除条件与当前状态页。

> 纪律：四种状态都必须落到 audit receipt 才算有效判定；只有 PASS 且证据齐备的案例才允许进入知识库的成功经验区。

## 6. 里程碑与时间安排

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| D1 | 资源、账号、地域、权限确认 | 云能力确认表完成 |

## 7. 评估与证据原则

- benchmark 结果评估与 AgentLoop 轨迹评估分开报告；
- 受控 adapter benchmark 不得替代真实 AgentTeams Trace；
- 任何云产品功能必须同时记录账号、地域、版本、调用方式和限制；
- 失败案例必须保留，不能只展示成功路径；
- 评测数字、架构图、Demo 口播和声明矩阵必须使用同一事实源；
- 未完成能力统一使用 `NOT_VERIFIED`、`DESIGN_ONLY` 或 `BLOCKED_UPSTREAM`。

## 8. 答疑会需要确认的关键结果

答疑会结束时，至少要拿到以下结论：

1. 是否可获得 AgentLoop 账号、AgentSpace 和 License Key；
2. AgentTeams/HiClaw 应使用 LoongSuite Pilot、Python 探针还是 util-genai 手动埋点；
3. PolarDB RAG 可申请的引擎、地域、模型和额度；
4. AgenticDB Branch 支持的 PolarDB 引擎和公测申请方式；
5. 是否有脱敏测试数据或可用的示例数据库；
6. 复赛允许使用哪些云服务和外部账号；
7. 评委希望看到“真实云上闭环”还是接受“本地闭环 + 云能力设计”；
8. 复赛材料是否允许在答疑后追加版本或补充证据；请一并确认最终提交截止时间与答辩形式（现场 / 录屏 / 远程共享屏幕）。

## 9. 当前决策
